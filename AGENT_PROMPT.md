# static studio: правила проекта

личный инструмент для заметок и небольших страниц. основной сценарий: выбрать заметку или пустую страницу, добавить своё содержание, проверить вид, сохранить проект или скачать готовую страницу.

## интерфейс

- шапка с логотипом, историей, меню проекта, предпросмотром и кнопкой скачивания;
- содержание и оформление в отдельных вкладках;
- список показывает содержание блоков, действия находятся у полей редактирования;
- служебные сообщения появляются после действия или при ошибке;
- мягкие скругления, спокойный гротеск в интерфейсе, светлый фон и зелёный акцент;
- настройки страницы меняют только страницу;
- компьютер и телефон, клавиатура, фокус, reduced motion и пустые состояния проверяются перед публикацией.

## содержание

все авторские подписи, начала предложений и названия брендов пишутся строчными: static studio, github, json, zip. длинные тире не используются. пользовательское содержание и технические идентификаторы сохраняют свой регистр. применяются `/Users/timofeychebaturkin/Documents/projects/chebaturkin-style/SKILL.md` и связанные справочники; для ясности также `/Users/timofeychebaturkin/Documents/projects/chebaturkin-copy/SKILL.md`.

## поведение

пять типов блоков: заголовок, текст, изображение, ссылка, разделитель. основы: заметка, пустая страница, инструкция, портфолио, афиша. новые блоки вставляются после текущего. действия и создание страницы можно отменить. загруженная картинка остаётся внутри проекта.

готовый zip содержит `index.html`, `styles.css` и локальные изображения в `assets/`. пустые блоки и подсказки редактора не экспортируются. json служит для продолжения работы. старые проекты v1/v2 должны открываться. история содержит 50 действий, текущая страница сохраняется в `localStorage`; при отказе хранилища пользователь получает предупреждение.

## технические границы

статичный сайт для github pages. без сборки и зависимостей во время работы. без аккаунтов, обязательного сервера, ключей api, платных сервисов, внешних моделей и облачной синхронизации. пользовательские файлы не отправляются на сервер. внешние картинки остаются сетевыми ссылками; локальный сценарий через json и zip работает самостоятельно.

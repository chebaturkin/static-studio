# план обновления редактора

цель: сделать static studio понятным личным инструментом для заметок и небольших страниц. выполняем задачи в текущей сессии, затем обновляем github и github pages.

## 1. тексты и сценарий

- [ ] заменить названия и подсказки в `index.html`, `app.js`, `404.html` и примере экспорта.
- [ ] убрать нумерацию, прописные подписи, длинные тире и постоянные служебные сообщения.
- [ ] добавить выбор основы с заметкой и пустой страницей в начале списка.
- [ ] добавить справку с сохранением, импортом и скачиванием.

## 2. интерфейс

- [ ] заменить сетку шапки на устойчивую компоновку с короткими действиями.
- [ ] обновить знак, цвета, типографику, скругления и состояния фокуса в `styles.css`.
- [ ] разделить содержание и оформление вкладками.
- [ ] перенести действия блока к его полям, дать списку всю ширину панели.
- [ ] проверить расположение элементов на пяти ширинах от 320 до 1440 px.

## 3. поведение

- [ ] написать и выполнить регрессионные тесты: новая страница, отмена, чистый экспорт и соответствие цветов.
- [ ] добавить новую страницу с сохранением предыдущей в истории.
- [ ] добавить выбор блока в предпросмотре и вставку после текущего блока.
- [ ] добавить палитры и изолировать настройки страницы от интерфейса.
- [ ] показывать ошибки сохранения и импорта, сохранить совместимость json.

## 4. проверка

- [ ] выполнить `npm test` и `node --check app.js`.
- [ ] пройти сценарии в браузере: заметка, блоки, история, палитры, картинка, json и zip.
- [ ] проверить клавиатуру, мобильный просмотр, пустые состояния и reduced motion.
- [ ] открыть распакованный экспорт, сверить оформление с предпросмотром.

## 5. github

- [ ] обновить `README.md`, `AGENT_PROMPT.md`, скриншот и описание репозитория.
- [ ] ограничить публикацию файлами приложения и добавить проверку тестов в workflow.
- [ ] отправить проверенные изменения и дождаться github pages.

проверки используют реальное состояние и скачанные файлы, а не копию реализации. исходные шесть тестов прошли перед началом работы.
